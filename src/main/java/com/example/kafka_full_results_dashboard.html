Breakpoint: between 10K and 100K msg/s. Hardware ceiling confirmed at ~88K msg/s. The 100K run shows p99 spiking to 2,230 ms — producer was queuing internally, unable to keep up. Unlimited run is cleaner (483 ms max) because Kafka batches optimally without a rate governor forcing unnatural pacing.

Group 1 (small) hit the same race condition as before — 100K messages consumed in 37ms fetch window but rebalance took 3.3s and the tool only saw 1 message. Groups 2 and 3 both succeeded. Interestingly, the 1MB fetch-size group was slower (350K vs 644K msg/s) — it only completed 2 reporting intervals, suggesting it was still reading when the tool exited, not that larger fetches are slower.
